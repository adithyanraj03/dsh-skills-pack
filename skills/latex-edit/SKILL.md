# latex-edit

A polish pass that silently changes an equation or breaks a `\ref` costs more than it saves. Edit narrowly and prove the paper still builds.

## Before editing

1. Find the structure: the root file, `\input`/`\include` sections (e.g. `sections/*.tex`), the preamble (`preamble.tex` or the top of `main.tex`), and custom macros (`\newcommand`, `\providecommand`). Use `graft_map` / `graft_grep` if the folder is indexed, else grep.
2. Identify generated files: headers like `% generated by ... -- do not edit` (e.g. `generated/numbers.tex`, `generated/table_*.tex`). Numbers in the text that come from macros like `\NumRealTest` must stay macros.
3. Take a checkpoint of the files you will touch (see the `checkpoint` skill).
4. Build once before editing (see `latex-build`) so you know the baseline is clean.

## While editing

- Change only the section, paragraph or sentences the user named. Do not "improve" neighbouring text.
- Leave untouched unless explicitly asked: math environments and inline math, `\label`/`\ref`/`\eqref`/`\cref` keys, `\cite` keys, figure/table floats and their placement options, the preamble, document class options, custom macros, and the author block.
- Never replace a number macro with a typed number, or type a new result number by hand. New numbers come from the generator script or the results files (see `claim-check`).
- Keep one sentence per line in the parts you rewrite, so diffs show sentence-level changes. Do not reflow untouched paragraphs.
- Keep the paper's spelling convention (US or UK), terminology and notation. One name per concept.
- Use proper LaTeX: `~` before `\cite`/`\ref`, `--` for ranges, ``` `` '' ``` quotes, `\%`, `\emph` not `\textit` for emphasis if the paper does.
- Unresolved content: use the project's placeholder macro (e.g. `\TBD{...}`) rather than inventing text, numbers or citations.

## After each edit

1. Rebuild (latex-build) and confirm no new errors, undefined refs or citations.
2. Show the diff of what you changed (prose diff; for a non-git folder use `git diff --no-index <checkpoint file> <file>`).
3. If page count matters (venue limit), report the page count before and after.

## Stop when

- The requested edit is done, the paper builds clean, and the diff shows no changes outside the requested scope.

## Rules

- If the requested change needs touching math, results or claims, say so and ask before doing it.
- Do not change the meaning of a claim while "polishing" its wording. If a sentence's claim seems wrong, flag it instead.
- For prose style, apply academic-unslop to the text you rewrote only.
